# 旅のしるし — 京都の写真地図

ARカメラの撮影結果と撮影地点を保存し、同じ日の写真からルートを作る静的Webアプリです。既存のGitHub Pagesの `/map/` で動作します。サーバーやAPIキーの設定は不要です。

## 使い方

ARカメラで撮影すると、プレビューに「地図で記録する」が表示されます。初回は撮影時に位置情報の許可が求められます。地図に記録を選ぶと、合成写真・撮影日時・取得した位置と精度を保存して地図を開きます。位置取得が失敗しても写真は保存でき、写真の詳細から地点を手動指定できます。

地図の「この日のルート」から、撮影時刻順に２つ以上の地点を結びます。最初は直線の案です。「道に沿う候補を取得」は区間ごとの徒歩／車に対応し、道路に沿う線を表示します。電車・バスと手動の区間は自動検索せず、経由地点の追加・移動・並び替えで調整します。手動の経由地の番号をドラッグできます。写真そのものの位置は写真詳細から修正します。

地図を確認してチェックを入れ、「このルートで保存」を押した１日１件のルートだけを累計距離に加えます。同じ日の再保存は上書きされ、二重加算されません。距離は保存したポリラインからの概算で、実測値ではありません。ルート保存後の写真の追加や位置の変更はルートへ自動反映せず、変更の案内を表示します。

画面右上の方位磁石で北向きに戻り、その下の矢印で現在地を中心にします。現在地の中心表示中は黄色です。１本指で移動、２本指で回転・拡大縮小ができます。端末方位の表示には対応センサーと許可が必要です。方位が取得できないときは、向きを偽らず黄色い丸だけを表示します。

## 保存とバックアップ

写真とルートは同じオリジンのIndexedDB (`kyoto-travel-journal-v1`) に保存します。GitHubに写真や座標はアップロードしません。同じ端末でも、異なるブラウザやホーム画面アプリでは保存領域を共有できない場合があるため、ARカメラと地図は同じブラウザで開いてください。Safariのデータ消去やストレージ整理で記録が失われる場合があります。

設定の「すべて書き出す」で写真を含むJSONをダウンロードできます。「読み込む」は追加・同一ID／同一日付の上書きです。全データを検証してから１つのトランザクションで保存し、失敗した場合は既存データを保持します。読み込み上限は100MBです。

ピン色はピン数（5／15／30／60本）か確定ルート距離（5／20／50／100km）を選択できます。既存ピンの色は変えず、新規登録時の段階を残します。縮小制限は距離に応じて段階的に広がり、設定から解除可能です。離れた地域の写真がある場合は表示範囲を広げます。

## 外部サービス

地図ライブラリはMapLibre GL JS 5.6.1、地図タイルはOpenStreetMap標準タイルです。地図は現代の地理情報を古地図風に着色したもので、歴史資料の古地図ではありません。地図のオフライン一括ダウンロードは行いません。

道路の候補はFOSSGISのOSRM公開サーバー `routing.openstreetmap.de` を利用します。ユーザーが候補取得を押した時に経由地点の座標を送信し、写真は送信しません。リクエストは直列化し、１秒１回以下（1.1秒間隔）に制限します。サービスに可用性保証はなく、失敗・タイムアウト時は直線案のままとし、実際の道路経路として扱いません。電車・バスの路線検索は含みません。大人数での公開運用では、利用規約に応じて地図・経路プロバイダを見直してください。

撮影時はGPSを１回要求します。位置確定まで数秒かかる場合があるため、撮影時刻と位置取得時刻を別々に保持します。地図表示中のみ現在地表示用のGPSを使用し、座標履歴は保存しません。バックグラウンドの移動追跡は行いません。

## 構成と検証

`core.js` は日付・距離・ルート検証、`store.js` は保存処理、`camera-bridge.js` はARカメラとの接続、`app.js` は地図と記録画面です。ルートは確認前と確認済みを分け、保存失敗時は編集中の内容を残します。

リポジトリのルートで `node --test tests/travel-core.test.cjs` を実行できます。カメラ・GPS・方位・iOSでの共有・ピンチ操作は実機確認が必要です。

## 追加した写真の撮影場所・日時（2026-10-11）

「写真を追加」で元画像のEXIFを、画像の縮小より先にブラウザ内で読み取ります。GPS付きなら撮影地点の確認用地図を表示し、読み取った撮影日時と場所を確認してから保存できます。チェックを外すと手動指定に切り替えられます。日時がない場合は入力が必要です。

DateTimeOriginalを優先し、なければCreateDateを使用します。OffsetTimeOriginal／OffsetTimeDigitizedがあればその時差を適用して日本時間で表示し、時差がない場合は日本時間と仮定した旨を表示します。端末のタイムゾーンやファイルの更新日時を撮影日時として代用しません。

EXIF読み取りはMITライセンスのexifr 7.1.3（`vendor/` に同梱）を使用します。JPEG・PNG・HEIC/HEIF・AVIFのメタデータと、WebPのEXIFチャンクに対応します。画像自体の表示・縮小はブラウザのデコード機能に依存するため、対応しない形式はJPEG/PNGで追加してください。写真の選択時にOSやアプリが位置情報を除去した場合は、元の写真に情報があっても読み取れないことがあります。

読み取った元のGPSと日時は新規写真の `originalMetadata` に保持し、地点の手動変更やバックアップ書き出し・読み込みでも保持します。すでに登録された写真の地点・日時を自動で変更することはありません。縮小保存した画像ファイル自体にはEXIFを再埋め込みしないため、記録をまとめて移すにはJSONバックアップを使用してください。


## １日の記録画像

「この日の記録を画像にする」から、選択日のすべての写真、または１〜５枚の写真ピンを選び、地図・その日の確定ルート距離・写真を１枚のPNGにまとめられます。画像を確認してから保存・共有します。写真は撮影時刻順で、ピン番号は日付内の元の番号を保持します。画像は長押しでも保存できます。

地図の範囲と確定ルート距離は１日全体を表し、選択モードでは選んだ写真のピンと写真カードだけを掲載します。ルートがない日は距離を「未確定」と表示し、未保存の編集中ルートや累計距離を使いません。位置未設定の写真も画像に含めます。すべての地点が未設定でルートもない場合は、無関係な地図を表示せず「地図なし」とします。

確認画面の地図が読み込み完了した後にWebGLの描画を取り込み、ピンは投影座標から画像に描きます。OpenStreetMapの出典も画像内へ含めます。地図の事前一括取得は行いません。生成処理と写真の合成はブラウザ内だけで実行し、写真・記録データは変更しません。

写真は切り抜かずに全体が見えるよう配置します。写真が多い日は縦長にし、1200万ピクセル・最長辺16000px以内になるよう縮小して、全写真を含めます。大量の写真では文字や画像が小さくなるため、細部を見せたい場合は５か所選択を利用してください。

### 写真情報の編集

メモ・手動地点・ピン色の編集は既存の `settings` ストアに写真ID別の差分として保存し、画像Blobを含む元の写真レコードを上書きしません。読み込み・画像出力・バックアップでは差分を統合し、写真の削除・バックアップによる置き換えでは対応する差分も同一トランザクションで削除します。保存形式のバージョン変更や既存写真の一括変換はありません。メモ保存時は一覧画像の要素とBlob URLを維持します。

編集の回帰テストは `tests/photo-details.test.cjs` 冒頭のコマンドで実行できます（jsdom 26 / fake-indexeddb 6 を使用）。
